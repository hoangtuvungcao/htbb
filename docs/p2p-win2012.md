# Máy chủ thử P2P trên Windows Server 2012 (nhánh `p2p`, Peerova nhúng)

Nhánh `p2p` nhúng **Peerova** (P2P trực tiếp xuyên NAT, mã hoá Noise IK đầu-cuối — mã nguồn ở `p2p/peerova/`, bản
của chủ dự án 01/11/2026; khi không nối thẳng được, Peerova mới tự dùng **đường dự phòng mã hoá qua website**
`peerova.pages.dev` rồi tự nâng lên đường thẳng khi được — tắt bằng `sv.p2p_relay=0`) vào game server Java qua **JNI** (không tiến trình phụ), và vào client PC Java / Android (JNI) / Unity PC
(C# P/Invoke). Đây là **bản thử**, chưa lên production.

## Cách chạy

```
Người chơi PC / Android / Unity                          Windows Server 2012
  game -> socket 127.0.0.1:<cổng tự chọn>                 htbb-server.jar (Java 8 64-bit)
       -> Peerova (trong tiến trình)  ===UDP/TCP P2P===>   Peerova (JNI, peerova_jni.dll)  -> 127.0.0.1:19129 (cổng game)
Người chơi J2ME (điện thoại cũ)  -------- TCP thẳng ----->                                    cổng game 19129
```

- Máy chủ: `sv.p2p=1` -> lúc khởi động `com.htbb.p2p.MayChuP2P` mở Peerova trên `sv.p2p_port` (UDP, + TCP cùng số làm
  đường dự phòng khi mạng chặn UDP), expose đúng cổng game `sv.port`. Mỗi kết nối P2P là một kết nối TCP loopback vào
  chính cổng game, nên giao thức game / `io.Session` không đổi. Máy chủ lấy **IP thật** của người chơi sau tunnel
  (`MayChuP2P.ipThat`), nên chống DoS / chặn IP / nhật ký `[CLIENT] ... ip=` vẫn theo từng người chơi.
- Người chơi đi qua đường dự phòng (relay) thì máy chủ không biết IP thật: phiên đó mang IP `127.0.0.1` (proxy tin cậy,
  như sau WAF hiện nay) — giới hạn theo tài khoản / thiết bị vẫn giữ.
- **TICKET** (`pvt_...`) là "địa chỉ" máy chủ: chứa khoá công khai + các địa chỉ (LAN / IP public / IPv6) của máy chủ.
  Máy chủ in ticket ra cửa sổ (`[P2P] TICKET ...`), ghi `p2p\ticket.txt`, và nút **Ticket P2P** ở chân AdminPanel
  (chép vào clipboard). Giữ `p2p\server.key` thì ticket không đổi khi khởi động lại — **nhưng đổi IP máy chủ là đổi
  ticket** (phải build / phát lại client).
- Client: bản build có ticket thì **mọi** kết nối game đi qua P2P (`javax.microedition.io.Connector` của PC / Android,
  `Session_ME.doConnect` của Unity). P2P lỗi -> hộp "Không kết nối P2P được tới máy chủ: ..." — **không** lùi về TCP
  thẳng (quyết định của chủ dự án). Bản build không có ticket chạy như cũ (TCP thẳng).
- **J2ME không dùng được P2P**: MIDP không nạp được thư viện native (không có JNI / FFI), nên jar J2ME vẫn nối TCP thẳng
  vào cổng game 19129. Muốn giữ người chơi J2ME thì phải mở TCP 19129 như trước.

## Cài trên Windows Server 2012 / 2012 R2

Peerova cho Server 2012 build bằng target `x86_64-win7-windows-gnu` (rustc stable chỉ còn hỗ trợ Windows 10+); script
build kiểm DLL không import API chỉ có từ Windows 10. Đã kiểm trên wine (Windows 10 giả lập) với JDK Windows 64-bit;
**chưa chạy trên Server 2012 thật**.

1. **Java 8 64-bit**: cài Eclipse Temurin 8 (x64, JRE hoặc JDK) — bản `.msi` x64. Kiểm: `java -version` phải có
   `64-Bit Server VM`. Java 32-bit KHÔNG nạp được `peerova_jni.dll`. (Java 11/17/21 64-bit cũng chạy.)
   Server 2012 cần các bản cập nhật Windows mới nhất (KB2919355 cho 2012 R2) để có TLS 1.2 (gia hạn license, bên dưới).
2. **MariaDB 10.6 (x64, .msi)** (không dùng MySQL 8 — login server cần hàm `PASSWORD()`). Trong `my.ini` mục
   `[mysqld]` thêm `lower_case_table_names=1` và `character-set-server=utf8mb4` (giống `vps/htbb-mariadb.cnf`), khởi
   động lại dịch vụ MariaDB. Tạo user và nạp CSDL (cmd ở thư mục gói):
   ```
   mysql -u root -p -e "CREATE USER 'htbb'@'127.0.0.1' IDENTIFIED BY 'MAT_KHAU'; CREATE USER 'htbb'@'localhost' IDENTIFIED BY 'MAT_KHAU';"
   mysql -u root -p --default-character-set=utf8mb4 < sql\htbb.sql
   mysql -u root -p -e "GRANT ALL ON htbb_db.* TO 'htbb'@'127.0.0.1','htbb'@'localhost'; GRANT ALL ON account.* TO 'htbb'@'127.0.0.1','htbb'@'localhost';"
   ```
3. **Chép gói**: trên máy build chạy `sh p2p/build/dong-goi-win2012.sh` -> `p2p/out/win2012/HTBB-P2P-Win2012.zip`
   (game server build nhánh p2p, `lib`, `map`, `cMap`, login server, `p2p\peerova_jni.dll` + `p2p\peerova.exe` bản
   win7, `run-p2p.bat`, `open-firewall.bat`, `server.ini.p2p.example`, `sql\htbb.sql`). Giải nén ra ví dụ `C:\htbb\`.
   Thư mục chứa đường dẫn không dấu.
4. **server.ini** (`C:\htbb\server\server.ini`): chép từ `vps\server.ini.linux.example`, sửa `db.*` (host
   `127.0.0.1:3306`, user / mật khẩu ở bước 2), `sv.pathLog=logs/`, `db.run=`, rồi **thêm cuối tệp** khối
   [`server.ini.p2p.example`](../p2p/win2012/server.ini.p2p.example) (`sv.p2p=1`, `sv.p2p_port=47000`,
   `sv.p2p_license=`...). Login server: `server\loginServer\server.ini` từ `vps\loginServer.server.ini.example`
   (`db.url=jdbc:mysql://127.0.0.1:3306/account?characterEncoding=UTF-8`, user / mật khẩu).
5. **License Peerova**: điền `sv.p2p_license=PVA-XXXXX-XXXXX-XXXXX-XXXXX` (tạo trên https://peerova.pages.dev). Không
   điền = gói DEV: **tối đa 3 người chơi P2P cùng lúc** (máy chủ in cảnh báo; người thứ 4 bị từ chối). License là bí mật:
   chỉ ở `server.ini` trên máy chủ (không vào git, không in ra log). Lease gắn với **machine id + khoá máy chủ**
   (`p2p\server.key`), kích hoạt trên chính máy Server 2012 (tính vào số máy chủ của gói), gia hạn ngầm 6 giờ/lần qua
   **HTTPS ra ngoài tới `peerova.pages.dev`** — firewall / proxy phải cho máy chủ ra cổng 443 tới tên miền đó (mất mạng
   tới web tối đa 7 ngày vẫn chạy). Cùng tên miền đó còn là điểm hẹn (`sv.p2p_rdv`) và đường dự phòng (`sv.p2p_relay`):
   máy chủ giữ sẵn kết nối WebSocket/TLS ra ngoài tới đó.
6. **Mở cổng** (chạy `open-firewall.bat` bằng *Run as administrator*): UDP + TCP `sv.p2p_port` (47000) cho Peerova,
   TCP 19129 chỉ khi còn người chơi J2ME. **Không** mở 8023 (login server nội bộ) và 3306. Máy chủ nằm sau router: chuyển
   tiếp (port-forward) UDP+TCP 47000 về máy chủ, hoặc để `sv.p2p_upnp=1` nếu router bật UPnP. Máy chủ có IP public trực
   tiếp: chỉ cần firewall.
7. **Chạy**: bấm đúp `server\run-p2p.bat` (kiểm Java 64-bit + `p2p\peerova_jni.dll`, mở login server ở cửa sổ riêng
   rồi game server). Thấy `[P2P] Peerova SAN SANG` + `[P2P] TICKET pvt_...` là xong; `[P2P] LOI: ...` = xem lỗi (thiếu
   DLL / Java 32-bit / cổng UDP bị chiếm). Chẩn đoán mạng: `server\p2p\peerova.exe doctor`.
8. **Phát ticket cho client**: lấy ticket (`p2p\ticket.txt` hoặc nút Ticket P2P), build client trên máy build:
   ```sh
   sh p2p/build/build-peerova.sh                     # native: win7 (Server 2012 + PC), win10, linux, android
   sh p2p/build/sync-java.sh                         # chép mã Java p2p vào server / client_pc / client_apk
   # PC Java (jar có sẵn peerova_jni.dll + .so, NativeLoader giải nén vào %APPDATA%\HTBB\p2p):
   PHIEN_BAN=0.9.30-p2p BAN=930 MAY_CHU=<ip>:19129 P2P_TICKET_FILE=ticket.txt sh client_pc/build.sh   # đường dẫn tương đối tính từ thư mục đang đứng
   # Android (bản debug com.htbb.pokemon.thu - cài song song bản chính thức):
   PHIEN_BAN=0.9.30-p2p BAN=930 MAY_CHU=<ip>:19129 P2P_TICKET_FILE=$PWD/ticket.txt OUT=HTBB-android-p2p.apk sh client_apk/build-pokemon.sh
   ```
   PC còn đổi được ticket lúc chạy: `--p2p-ticket pvt_...`, biến `HTBB_P2P_TICKET`, hoặc `p2p_ticket=` trong
   `cai_dat.properties`. **Cổng trong `MAY_CHU` phải bằng `sv.port` của máy chủ** (client P2P xin đúng cổng đó; host
   bị bỏ qua — ticket quyết định máy chủ). Unity PC (C# binding `Peerova.Tunnel`, `Assets/Plugins/Peerova/Peerova.cs` chép bởi
   `sync-java.sh`, dùng ở `P2PPeerova.cs` + `Session_ME.doConnect`): chép `p2p/out/dist/windows-x86_64-win7/peerova.dll`
   vào `client_pc_ios/Assets/Plugins/x86_64/` (Import Settings: Standalone Windows x86_64), build với
   `P2P_TICKET=pvt_...` (hoặc `-htbbP2PTicket`), lúc chạy đổi được bằng `-htbbP2PTicket pvt_...` / `HTBB_P2P_TICKET` —
   **chưa build / chạy trong Unity** (máy dev không có Unity; cùng mã C# đã chạy trên .NET 8 tới game server qua P2P).

## Phiên bản bản thử

`PHIEN_BAN=0.9.30-p2p`, `BAN=930` truyền qua biến môi trường lúc build (KHÔNG sửa `tools/phat-hanh/phien_ban.conf`):
nhãn người chơi thấy khác hẳn bản chính thức `0.9.30-opentest`; số bản 930 giữ nguyên = không bao giờ "mới hơn" bản phát
hành nào (không tranh số với 0.9.31+ sau này, máy chủ chính thức không coi là bản lạ); APK thử là gói `.thu` riêng.

## Giới hạn / việc còn mở

- J2ME: không P2P (xem trên).
- Ticket chứa IP máy chủ: đổi IP / mạng -> ticket mới -> client phải có ticket mới (build lại hoặc `--p2p-ticket`).
  Hướng dài hạn: client tải ticket từ website, hoặc mã kết nối 6 ký tự của Peerova (`share`).
- Không license: 3 CCU P2P.
- Dưới wine, lần đăng ký điểm hẹn website đầu tiên của server báo lỗi (đường dự phòng thì sẵn sàng): kiểm lại trên
  Server 2012 thật bằng `p2p\peerova.exe doctor` và log `[P2P] điểm hẹn website`.
- Đường dự phòng (relay) chưa được ép thử trong HTBB (máy dev cùng LAN luôn đi thẳng); IP người chơi qua relay = 127.0.0.1.
- Cả hai bên sau NAT symmetric ngẫu nhiên không nối được (giới hạn chung, không relay); máy chủ có IP public / port-forward
  thì mọi mạng người chơi đều vào được.
